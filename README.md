AgentHub（AI 多智能体协作与治理平台）
一、 项目愿景与核心思想
“大厂在制造聪明的数字员工，而我们为数字员工制定劳动法与组织架构。”

现有的 AI Agent 框架（如 LangChain、AutoGen）大多聚焦于“如何让模型更聪明地调用工具”，却忽视了“概率性系统带来的失控风险”与“多角色协作的权责边界”。本项目基于“状态机驱动”与“最小权限原则”，致力于打造一套高可用、可观测、防呆且安全的 AI 团队编排治理系统。

核心哲学： 框架是基于思想创作的。我们不造黑盒，我们造带安防系统的赛博办公室。

二、 解决的核心痛点
黑盒失控：大模型幻觉导致乱执行破坏性命令。

沟通错位：技术 Agent 与业务 Agent 之间、AI 与人类之间语言不通。

权责不清：多 Agent 并发时，谁调用、谁审批、谁兜底，边界模糊。

上手门槛高：过度依赖手打 Prompt，无法让不懂技术的普通用户无缝接入。

三、 核心架构设计
1. 编排层 (Orchestration Layer) —— 系统的“大脑”
状态机引擎 (State Machine)：所有任务必须遵循 PENDING -> CODING -> REVIEWING -> DONE/FAILED 的硬性流转，杜绝任务越级乱跳。

即插即用总线 (Plugin Bus)：底层对接大模型（LLM Provider 可无缝切换）；上层对接原子技能（通过 @AgentSkill 注解自动注册）。

2. 治理与安全层 (Governance Layer) —— 系统的“御史台”
数字镜像权限 (Digital Twin RBAC)：Agent 的权限严格 ≤ 其人类主人的权限。

动态熔断与急停 (Human-in-the-loop)：针对高危指令（如 SHELL_EXEC），状态机强制挂起，前端弹出物理级“急停按钮”，等待人类审批。

沙箱隔离：非信任代码与技能执行，必须运行在受限的 Docker 沙箱内。

3. 多租户协作层 (Collaboration Layer) —— 系统的“朝堂”
一人一 Agent：团队成员各自拥有专属的“数字副官”，代替其进行高频横向对接。

内网交流面板 (War Room)：基于 WebSocket 的实时通信总线。Agent 之间的协作以结构化 JSON 流转，并在前端渲染为“群聊工单”。

4. 交互与可观测层 (UX & Observability) —— 系统的“全息驾驶舱”
双轨制语言协议 (Dual-track Protocol)：专家 Agent 之间使用高密度的“术语/协议”通信；对外输出给普通用户的，强制经过“翻译层”，转化为“大白话”。

桌面悬浮小人 (Desktop Pet Agent)：始终置顶的桌面精灵。实时映射 Agent 状态（敲键盘=编码中，冒烟=发生异常，流泪=崩溃），并提供“抛按钮”交互（批准/打回/急停）。

点点点模式 (No-Code UI)：摒弃手写 Prompt，通过表单下拉、拖拽节点、点击决策，完成复杂开发流。

四、 典型工作流演示 (Workflow)
需求输入：人类在面板点击“新建任务”，勾选“拍卖系统-高并发防重”。

任务拆解：@PM Agent 将大需求拆为 3 个原子任务，生成清单推送到面板。

人工审批：人类点击【同意】。任务进入 CODING 状态。

自动执行：@Dev Agent 自动生成代码，触发 @QA Agent 自动拉取并运行 JUnit 测试。

异常告警：测试发现并发死锁，@QA Agent 发出 FAILED 报告。桌面小人开始“抱头蹲防”，抛出【打回重写】按钮。

干预与闭环：@Dev Agent 自动根据报错调整代码，重新提交测试并 PASSED。

五、 技术选型与实施路线图 (Tech Stack & MVP)
后端：Spring Boot 3 + JDK 17 + Spring AI (或 LangChain4j)

前端：Vue 3 + WebSocket + 简易 SVG/像素小人 (可使用 Tauri 打包为桌面端)

存储：单机 Map/SQLite (MVP阶段) / MySQL + Redis (进阶阶段)

MVP 演进路线：

Phase 1 (单体起步)：手写极简状态机，跑通单 Agent “需求->生成->人工审批”闭环。

Phase 2 (引入权限)：开发 @RequirePerm 切面，实现底层技能越权拦截。

Phase 3 (双轨通讯)：加入翻译适配层，接入 WebSocket，做出一期“内网聊天面板”。

Phase 4 (桌面精灵)：脱离浏览器，实现 Tauri/JavaFX 悬浮窗，映射系统状态。

Phase 5 (治理体系开源)：剥离业务，将状态机与权限网关作为独立中间件开源。

六、 开发守则（防破军天空陷阱）
不造无意义的轮子：大模型调用依赖成熟框架，精力全部投入在“编排与治理”。

警惕过度设计：坚决不用微服务，死磕模块化单体（Modular Monolith）。

保持白盒底线：黑盒防呆给用户，白盒代码开源给高级开发。
